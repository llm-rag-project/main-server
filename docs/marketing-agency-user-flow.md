# 뉴스 인텔리전스 콘솔: 마케팅회사 실무자 관점 사용 흐름 분석

## 1. 문서 목적

이 문서는 뉴스 기사, SNS 신호, AI 요약, 중요도 계산, 이메일 보고서, Dify 지식베이스 연동을 기반으로 하는 현재 프로그램이 실제 마케팅회사 직원에게 어떤 업무적 도움을 줄 수 있는지 구체적으로 분석한다.

주요 관점은 다음과 같다.

- 브랜드/기업 모니터링 담당자가 매일 어떤 순서로 이 도구를 쓰는가
- 클라이언트 보고, 이슈 대응, 캠페인 기획에 어떤 정보를 제공할 수 있는가
- 현재 기능이 실무 흐름에서 어디까지 충분하고, 어디서 보강이 필요한가
- 앞으로 어떤 방향으로 제품을 고도화해야 하는가

## 2. 핵심 사용자 정의

### 2.1 주요 사용자

이 프로그램의 핵심 사용자는 마케팅회사, PR회사, 디지털 에이전시, 브랜드 컨설팅 조직의 실무자다.

대표 역할은 다음과 같다.

- 브랜드 모니터링 담당자
- PR/언론홍보 AE
- 디지털 캠페인 운영자
- 클라이언트 리포트 작성 담당자
- 이슈/위기 대응 담당자
- 브랜드 전략 플래너

### 2.2 사용자의 주요 고민

이 사용자는 단순히 기사를 많이 모으고 싶은 사람이 아니다. 매일 다음 질문에 빠르게 답해야 한다.

- 오늘 우리 클라이언트 브랜드에 무슨 일이 있었는가
- 중요한 기사는 무엇이고, 왜 중요한가
- 부정 이슈가 생겼는가
- 홍보성 기사와 자발적 보도는 어떻게 다른가
- SNS에서는 언론과 다른 반응이 있는가
- 클라이언트에게 지금 보고해야 하는가, 지켜봐도 되는가
- 내부 회의에서 어떤 근거 자료를 가져가야 하는가
- 보고서에 넣을 수 있는 요약 문장과 그래프가 있는가

## 3. 현재 프로그램이 제공하는 핵심 가치

### 3.1 키워드 기반 브랜드 모니터링

사용자는 브랜드명, 기업명, 제품명, 캠페인명, 경쟁사명, 주요 이슈어를 키워드로 등록한다.

키워드 등록 시 다음 설정을 함께 지정할 수 있다.

- 키워드명
- 수집 주기
- 최대 수집 개수
- 이메일 자동 전송 여부
- 이메일 발송 시간
- 수신자 목록

실무적 의미:

- 브랜드별 모니터링 룰을 개별적으로 운영할 수 있다.
- 중요 브랜드는 짧은 주기로, 일반 브랜드는 긴 주기로 수집할 수 있다.
- 클라이언트별 수신자를 다르게 설정해 데일리 리포트를 자동화할 수 있다.

### 3.2 뉴스 기사 수집

키워드별로 뉴스 기사를 수집하고, 기사 원문을 크롤링한다.

실무적 의미:

- 담당자가 직접 포털 검색을 반복하지 않아도 된다.
- 수집 주기와 수집 개수에 따라 모니터링 강도를 조절할 수 있다.
- 기사 원문을 확보해 AI 요약, 중요도 분석, Dify 지식베이스 질의에 활용할 수 있다.

### 3.3 AI 요약

수집된 기사는 자동으로 요약된다.

실무적 의미:

- 담당자가 기사 전체를 읽기 전에 핵심 내용을 빠르게 파악할 수 있다.
- 내부 공유나 클라이언트 보고서 초안 작성 시간이 줄어든다.
- 중요 기사 Top 5를 확인할 때 제목만 보는 것보다 판단 속도가 빨라진다.

### 3.4 AI 중요도 계산

기사는 중요도 점수와 판단 근거를 갖는다.

실무적 의미:

- 기사 목록을 단순 최신순이 아니라 업무 우선순위 기준으로 볼 수 있다.
- 담당자가 오전에 먼저 읽어야 할 기사와 나중에 봐도 되는 기사를 구분할 수 있다.
- 클라이언트 보고에 넣을 기사 후보를 빠르게 좁힐 수 있다.

### 3.5 감성/홍보성 분석

기사는 AI 분석을 통해 긍정, 부정, 중립 등으로 분류되고, 홍보성 여부도 판단된다.

실무적 의미:

- 부정 기사 비중이 높아지는 시점을 빠르게 감지할 수 있다.
- 광고성 기사와 자발적 보도, 즉 earned media를 분리해 볼 수 있다.
- 캠페인 성과 보고에서 "기사 수"만이 아니라 "질적 노출"을 설명할 수 있다.

### 3.6 SNS 24시간 신호

현재 SNS 지표는 플랫폼별 공식 API가 있으면 공식 API를 사용하고, 없으면 최근 24시간 공개검색 샘플로 보조 신호를 제공한다.

현재 구조:

- YouTube: API 키가 있으면 공식 YouTube Data API 기반
- X/Twitter: Bearer Token이 있으면 공식 Recent Counts API 기반
- Instagram, Reddit, 커뮤니티: 제한적으로 공개검색 샘플 기반

실무적 의미:

- 언론 보도와 SNS 확산의 차이를 볼 수 있다.
- 언론에는 작게 보이지만 SNS에서 확산되는 이슈를 감지할 수 있다.
- SNS 지표는 "정확한 전체 검색량"이 아니라 신호로 해석해야 한다.

### 3.7 이메일 보고서

키워드별 또는 전체 기준으로 데일리 리포트를 이메일로 보낼 수 있다.

보고서에는 다음 정보가 포함된다.

- 전체 기사 수
- AI 요약 완료 수
- 중요도 계산 완료 수
- SNS 언급 신호
- 키워드별 기사 수
- 감성 분포
- 일자별 기사 추이
- SNS 플랫폼별 신호
- 중요 기사 요약
- Excel 첨부 파일

실무적 의미:

- 매일 아침 담당자가 직접 보고서를 만들지 않아도 된다.
- 클라이언트에게 전달 가능한 기본 브리핑 자료를 자동 생성할 수 있다.
- 내부 팀장, AE, 클라이언트 담당자가 같은 정보 기준을 공유할 수 있다.

### 3.8 AI 채팅

수집된 기사와 Dify 지식베이스를 기반으로 AI 채팅을 사용할 수 있다.

실무적 의미:

- "최근 이 브랜드 부정 이슈 요약해줘"
- "클라이언트 보고용 5줄 요약 만들어줘"
- "위기 대응 관점에서 중요한 기사만 뽑아줘"
- "이번 주 기사 흐름을 캠페인 성과 관점으로 정리해줘"

같은 질문을 할 수 있다.

## 4. 실무 사용 흐름

### 4.1 초기 세팅 흐름

사용자는 먼저 관리할 브랜드나 기업을 키워드로 등록한다.

예시:

- 동국대학교
- 삼성전자
- LG전자
- 현대자동차
- 특정 캠페인명
- 특정 CEO명
- 제품명
- 경쟁사명

등록 시 판단 기준:

- 매일 봐야 하는 핵심 브랜드는 1일 또는 6시간 단위
- 위기 가능성이 있는 브랜드는 1시간 또는 3시간 단위
- 일반 시장 트렌드 키워드는 1일 또는 7일 단위
- 클라이언트에게 바로 공유해야 하는 브랜드는 이메일 자동 발송 켜기

### 4.2 매일 아침 확인 흐름

마케팅회사 직원은 출근 후 보통 다음 순서로 확인한다.

1. 이메일 보고서 확인
2. 프로그램 접속
3. 통계 탭에서 선택 브랜드 브리핑 확인
4. 중요도 높은 기사 Top 5 확인
5. 부정 신호와 SNS 신호 확인
6. 필요 시 기사 탭에서 원문 확인
7. 클라이언트 보고 또는 내부 공유 여부 판단

이때 프로그램이 특히 도움되는 지점:

- 오늘 읽어야 할 기사만 먼저 보여준다.
- 부정 비중, SNS 확산, 광고성 비중을 한 화면에서 확인한다.
- 이메일 보고서와 대시보드가 같은 기준을 사용한다.

### 4.3 이슈 발생 시 흐름

부정 기사나 SNS 신호가 올라가면 사용자는 다음 행동을 한다.

1. 통계 탭에서 부정 비중과 SNS 부정 힌트 확인
2. 우선순위 기사 목록에서 상위 기사 확인
3. 기사 원문 링크 확인
4. AI 채팅으로 이슈 요약 요청
5. 클라이언트 보고용 문장 생성
6. 필요 시 Excel 보고서 다운로드
7. 내부 대응 회의에 공유

예시 질문:

- "이 이슈를 클라이언트에게 보고할 수 있게 5줄로 정리해줘"
- "부정 여론의 핵심 원인을 기사 기준으로 정리해줘"
- "위기 대응 메시지 초안을 만들어줘"
- "지금 당장 대응이 필요한 수준인지 판단해줘"

### 4.4 캠페인 성과 확인 흐름

캠페인 집행 중인 브랜드는 기사 수만 많다고 좋은 게 아니다. 사용자는 다음을 본다.

- 기사 수 증가 여부
- 긍정/중립 기사 비중
- 광고성 기사 비중
- earned media 비중
- SNS 확산 신호
- 중요도 높은 매체 노출 여부
- 기사 제목과 요약에서 캠페인 메시지가 반영되는지

현재 프로그램에서 얻을 수 있는 도움:

- 캠페인 관련 기사 노출량 파악
- 기사 요약을 통해 메시지 반영 여부 빠르게 확인
- 홍보성 기사와 일반 기사 분리
- 보고서에 넣을 그래프와 요약문 확보

### 4.5 클라이언트 정기 보고 흐름

정기 보고 전 사용자는 다음 자료가 필요하다.

- 기간별 기사 추이
- 주요 기사 리스트
- 긍정/부정/중립 분포
- 주요 이슈 요약
- SNS 신호
- 중요 기사 근거
- 원문 링크

프로그램이 제공하는 산출물:

- Excel 보고서
- 이메일 HTML 본문
- AI 요약문
- 중요도 Top 기사
- 그래프 요약

## 5. 화면별 실무 가치 분석

### 5.1 좌측 키워드 목차

현재 역할:

- 관리 중인 키워드 목록 확인
- 키워드 선택
- 수집 주기, 최대 수집 개수, 이메일 설정 확인
- 키워드 추가
- 키워드 삭제

실무적 가치:

- 클라이언트별 브랜드를 빠르게 전환할 수 있다.
- 키워드별 운영 설정이 목록에서 바로 보인다.

개선 필요:

- 키워드 그룹 기능 필요
- 클라이언트명/브랜드명/캠페인명 계층 구조 필요
- 경쟁사 묶음과 단일 브랜드 키워드를 구분해야 함

### 5.2 통계 탭

현재 역할:

- 선택 키워드 브리핑
- 브랜드 헬스 점수
- 뉴스/SNS/감성/홍보성 지표
- 리스크 신호
- 기회 신호
- 추천 액션
- 중요 기사
- 그래프
- 보고서 다운로드/이메일 발송

실무적 가치:

- 담당자가 오늘의 상태를 가장 빠르게 파악하는 화면이다.
- 단순 데이터보다 판단 문장과 액션을 제공한다.

개선 필요:

- 헬스 점수 산식 설명 필요
- 전일 대비 변화량 강화 필요
- 기사량의 절대값보다 변화율, 급증 여부, 리스크 임계값이 더 중요함
- SNS 신호의 정확도 등급 표시 필요

### 5.3 기사 탭

현재 역할:

- 기사 목록 확인
- 요약 확인
- 중요도 점수 확인
- 원문 링크 접근

실무적 가치:

- 보고서에 넣을 기사 후보를 검토할 수 있다.
- 원문 확인이 필요한 기사를 빠르게 열 수 있다.

개선 필요:

- "보고서에 포함" 체크 기능
- 기사 태그 기능
- 담당자 메모 기능
- 중요 기사만 보기
- 부정 기사만 보기
- 매체별 필터

### 5.4 AI 채팅

현재 역할:

- 수집된 기사 기반 질문
- Dify 지식베이스 기반 대화

실무적 가치:

- 보고 문장 작성 보조
- 이슈 요약 보조
- 대응 방향 정리

개선 필요:

- 선택 키워드 컨텍스트 자동 주입
- 기간 필터 자동 반영
- "클라이언트 보고용", "내부 공유용", "위기 대응용" 프롬프트 버튼
- 답변에 기사 출처 링크 포함

## 6. 마케팅 실무자가 실제로 보고 싶어 할 추가 정보

### 6.1 전일 대비 변화

단순 기사 수보다 중요한 것은 변화다.

필요 지표:

- 전일 대비 기사 수 증감
- 전일 대비 부정 기사 증감
- 전일 대비 SNS 신호 증감
- 최근 7일 평균 대비 오늘 수치
- 급증 알림

실무 이유:

- 기사가 10건인 것보다, 평소 1건이던 브랜드가 10건으로 오른 것이 더 중요하다.

### 6.2 이슈 클러스터

기사 여러 개가 같은 이슈를 말하는지 분류해야 한다.

필요 기능:

- AI가 기사들을 이슈별로 묶기
- 각 이슈별 대표 기사 선정
- 이슈별 감성 분포
- 이슈별 확산 정도

예시:

- "신제품 출시"
- "가격 논란"
- "CEO 인터뷰"
- "대학 행사"
- "규제 이슈"

실무 이유:

- 기사 30건을 각각 보는 것보다, 이슈 4개로 묶어 보는 것이 보고서 작성에 훨씬 유리하다.

### 6.3 매체 영향력

모든 기사가 같은 가치가 아니다.

필요 기능:

- 주요 매체 여부
- 경제지/전문지/지역지/블로그성 매체 구분
- 매체별 기사 수
- 중요 매체 노출 여부

실무 이유:

- 기사 수는 적어도 주요 경제지에 나왔으면 보고 가치가 크다.

### 6.4 메시지 반영도

캠페인/PR 관점에서는 브랜드가 의도한 메시지가 기사에 반영됐는지가 중요하다.

필요 기능:

- 사용자가 핵심 메시지 입력
- 기사 제목/본문에서 메시지 반영 여부 AI 판단
- 반영된 문장 추출
- 미반영/왜곡 표현 감지

실무 이유:

- 클라이언트는 "얼마나 보도됐나"보다 "우리가 말하고 싶은 메시지가 전달됐나"를 궁금해한다.

### 6.5 경쟁사 비교

무관한 키워드끼리 비교하는 것은 의미가 없다. 하지만 경쟁사 그룹 안에서는 비교가 매우 중요하다.

필요 기능:

- 키워드 그룹 생성
- 그룹 유형 선택: 단일 브랜드, 경쟁사 비교, 캠페인, 이슈 모니터링
- 경쟁사 그룹 안에서만 점유율 비교
- Share of Voice 계산

실무 이유:

- 삼성전자와 동국대학교를 비교할 필요는 없지만, 삼성전자와 SK하이닉스는 비교 가치가 있다.

### 6.6 위기 등급

부정 기사 하나가 있다고 모두 위기는 아니다.

필요 기능:

- 위기 등급: 낮음, 주의, 경계, 심각
- 판단 근거:
  - 부정 기사 수
  - 주요 매체 여부
  - SNS 확산 여부
  - 반복 보도 여부
  - 법적/안전/불매/정치 키워드 포함 여부

실무 이유:

- 담당자는 "보고해야 하나?"를 빠르게 판단해야 한다.

### 6.7 보고서 자동 문장

보고서에는 숫자보다 문장이 필요하다.

필요 기능:

- 오늘의 한 줄 요약
- 클라이언트 보고용 5줄 요약
- 내부 회의용 상세 요약
- 리스크/기회/권장 액션 문장
- 전일 대비 변화 설명 문장

실무 이유:

- 실무자는 데이터를 복사하는 것이 아니라 보고 문장을 만들어야 한다.

## 7. 현재 프로그램의 한계

### 7.1 SNS 지표의 정확도 문제

현재 SNS는 공식 API가 없는 경우 공개검색 샘플 기반이다.

한계:

- Instagram 전체 게시글 수를 정확히 세기 어렵다.
- 공개검색에 잡히지 않는 게시물은 누락된다.
- 플랫폼별 검색 정책 변화에 영향을 받는다.

해결 방향:

- YouTube, X는 공식 API 키 기반으로 강화
- Instagram은 해시태그 중심 설계 또는 Meta Graph API 권한 확보
- SNS 지표에 정확도 등급 표시

### 7.2 Dify 지식베이스 기존 문서 추적 문제

현재 개선 이후부터는 Dify document id를 저장하지만, 과거 업로드 문서는 DB에 document id가 없다.

해결 방향:

- 신규 문서는 정확히 추적
- 기존 문서는 Dify 메타데이터 검색 가능 여부 확인 후 보정
- 보정 불가 시 신규 수집분부터 삭제 정책 적용

### 7.3 비교 구조 문제

무관한 키워드끼리 비교하면 실무적 의미가 약하다.

해결 방향:

- 키워드 그룹 기능
- 그룹 유형별 대시보드
- 단일 브랜드 화면과 경쟁사 비교 화면 분리

### 7.4 보고서 품질

현재 보고서는 기본 지표와 그래프를 제공하지만, 컨설팅 보고서 수준으로 가려면 더 많은 해석이 필요하다.

개선 방향:

- 이슈 클러스터별 보고
- 전일 대비 변화 문장
- 주요 매체 노출 분석
- 클라이언트용 executive summary

## 8. 권장 업데이트 로드맵

### 8.1 1순위: 키워드 그룹과 모니터링 목적 분리

필요 이유:

- 모든 키워드를 같은 방식으로 보면 안 된다.
- 단일 브랜드, 경쟁사 비교, 캠페인, 위기 이슈는 보는 지표가 다르다.

추가 기능:

- 그룹 생성
- 그룹에 키워드 배치
- 그룹 유형 선택
- 그룹별 대시보드

### 8.2 2순위: 전일 대비 변화와 급증 감지

필요 이유:

- 마케팅 실무자는 오늘 상태보다 변화 감지가 중요하다.

추가 기능:

- 기사 수 전일 대비
- 부정 비중 전일 대비
- SNS 신호 전일 대비
- 최근 7일 평균 대비
- 급증 배지

### 8.3 3순위: 이슈 클러스터링

필요 이유:

- 기사 목록은 정보가 너무 많다.
- 보고서는 이슈 단위로 작성된다.

추가 기능:

- AI 이슈 묶음
- 대표 기사
- 이슈별 요약
- 이슈별 리스크/기회

### 8.4 4순위: 보고서 자동 문장 고도화

필요 이유:

- 클라이언트에게 필요한 것은 해석된 문장이다.

추가 기능:

- Executive Summary
- 전일 대비 해석
- 리스크 브리핑
- 권장 액션
- 클라이언트 보고 톤 선택

### 8.5 5순위: SNS 공식 API 강화

필요 이유:

- SNS 신호가 보조 지표에서 핵심 지표가 되려면 정확도가 필요하다.

추가 기능:

- YouTube API 키 관리
- X Bearer Token 관리
- Instagram 해시태그 모니터링 설계
- 지표별 정확도 표시

### 8.6 6순위: 기사 선별/메모/보고서 포함 기능

필요 이유:

- 실무자는 자동 분석 결과를 그대로 쓰지 않고 최종 선별한다.

추가 기능:

- 보고서 포함 체크
- 내부 메모
- 기사 태그
- 담당자 코멘트
- 제외 처리

## 9. 최종 제품 방향

이 프로그램은 단순 뉴스 크롤러가 아니라, 마케팅회사 직원의 "브랜드 상황 판단 보조 도구"가 되어야 한다.

좋은 방향:

- 적은 클릭으로 오늘의 상황을 알려준다.
- 숫자보다 판단 문장을 제공한다.
- 기사를 이슈 단위로 묶는다.
- 클라이언트에게 바로 보낼 수 있는 보고서를 만든다.
- 위기 신호를 빨리 알려준다.
- 경쟁사 비교는 관련 그룹 안에서만 한다.
- AI 채팅은 수집 데이터와 근거 기사 링크를 기반으로 답한다.

피해야 할 방향:

- 무관한 키워드끼리 순위 비교
- 의미 없는 전체 카운트 나열
- 출처 없는 AI 요약
- 정확하지 않은 SNS 수치를 검색량처럼 표현
- 사용자가 다시 보고서를 손으로 많이 고쳐야 하는 구조

## 10. 한 줄 결론

이 프로그램의 핵심 가치는 "기사와 SNS를 많이 모으는 것"이 아니라, 마케팅 실무자가 매일 아침 클라이언트 브랜드의 상태를 빠르게 판단하고, 보고 가능한 형태로 정리해주는 것이다.

따라서 앞으로의 업데이트는 수집량 증가보다 다음 방향에 집중하는 것이 좋다.

- 선택 키워드 중심의 상황 판단
- 그룹 기반 경쟁 비교
- 전일 대비 변화 감지
- 이슈 클러스터링
- 보고서 문장 자동화
- Dify 지식 기반의 근거 있는 AI 채팅
- SNS 지표의 정확도 등급화
